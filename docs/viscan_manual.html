1 简介

1.1 什么是 Viscan？

Viscan 是一款基于 JavaFX 的桌面应用程序，旨在简化 Windows 系统下通过 WSL2（Windows Subsystem for Linux 2）执行生物信息学工具的流程。它提供图形化界面，使用户能够在无需直接操作命令行的情况下从宏基因测序样本中识别病原物种。

Viscan 支持的主要工具包括：

  • fastp —— 高速全功能 FASTQ 数据预处理（质量控制、过滤和报告生成）
  • Bowtie2 —— 高速、内存高效的 DNA 读段比对工具，用于宿主去除或参考基因组比对
  • Kraken2 —— 基于 k-mer 的宏基因组分类工具，可对读段进行快速物种鉴定
  • Recentrifuge —— 对 Kraken2 分类结果进行整理、统计和可视化，支持阴性对照比较

1.2 运行环境说明

Viscan 在以下环境中完成开发与测试：

项目 环境
操作系统 Windows 10
WSL WSL2
Java JDK 17
RAM 16 GB
ROM ≥50 GB

Viscan 理论上可在支持 WSL 的 Windows 系统上运行，但尚未在所有 Windows 版本或 WSL 版本上进行全面测试。

1.3 支持的工具一览

工具 功能说明
fastp FASTQ 数据质量控制与过滤，生成质控报告
Bowtie2 读段与参考基因组的比对（常用于宿主去除）
k2-classify 使用 Kraken2 进行序列分类鉴定
k2-download-library 下载物种基因组参考序列
k2-download-taxonomy 下载 NCBI 分类学信息
k2-build 根据现有的参考基因组序列构建 Kraken2 数据库索引
Recentrifuge 对分类结果进行置信度计算、多样品比较和可视化分析
Flow1 顺序执行质控、宿主去除与病原分类的预设分析流程

2 安装与配置

2.1 快速开始检查清单

  • 在 Windows 中安装并启用 WSL2
  • 下载并解压 Viscan 程序
  • 运行 viscan.bat 启动程序（默认使用一同分发的 Java 17 运行环境）
  • 在 Config 页面确认 WSL 可正常连接
  • 通过 Install 页面安装所需生物信息学软件，或在 Config 页面手动指定已安装软件的路径
  • 在 Status 页面确认所有工具状态为 Available

2.2 安装外部生信工具

Viscan 提供了便捷的安装界面，用于获取和管理所需的外部分析软件。

  1. 确保 WSL 环境已正确安装并处于运行状态。
  2. 在主界面中进入 Settings → Install 页面。
  3. 在该页面中配置环境存放路径，并选择各工具的安装版本。
  4. 单击 Install 按钮。GUI 将新建一个终端页面以执行安装流程，请等待其运行完成。
  5. 所有工具均通过 micromamba 进行环境创建与依赖管理，默认安装路径为 external/tools_env/。

2.3 配置 WSL 与工具路径

  1. 在主界面进入 Settings → Config 页面。
  2. 配置以下选项：

WSL 配置

  • WSL 可执行文件：wsl.exe 的路径（默认值：wsl）
  • WSL 发行版：所使用的 WSL 发行版名称（例如 Ubuntu、Arch，默认自动获取）

工具路径

  • fastp：fastp 二进制文件所在目录
  • Bowtie2：Bowtie2 二进制文件所在目录
  • Kraken2：Kraken2 二进制文件所在目录
  • Recentrifuge：Recentrifuge 二进制文件所在目录

通用设置

  • 工作目录：默认的文件操作目录
  • 线程数：默认使用的 CPU 线程数（默认值为系统可用处理器数）

2.4 状态检查

安装与配置完成后：

  1. 打开主界面 Settings → Status 页面
  2. 检查所有工具状态是否显示为 "Available"（可用）
  3. 验证 WSL 是否正常连接
  4. 查看各工具的运行状况

如果某个工具显示为 "Not Found"（未找到）：

  • 检查 Config 页面中该工具的路径设置是否正确
  • 如有必要，重新运行安装流程
  • 确认 WSL 连接正常

3 快速上手

本章节介绍 Viscan 的界面结构及标准分析流程，帮助用户快速完成一次宏基因组数据分析。

3.1 界面概览

3.1.1 顶部菜单栏

顶部菜单栏包含以下功能模块：

  • Tools：单个生物信息学工具的参数配置界面
  • Flow：预设分析流程的参数配置界面
  • Settings：外部工具安装、WSL 配置及全局参数设置

3.1.2 文件管理区域（左侧面板）

该区域用于样本文件的导入与管理。

添加文件

支持以下两种方式导入数据文件：

  • 通过浏览添加

    单击 "File" 或 "Folder" 按钮，在资源管理器中选择文件或文件夹。

  • 拖拽添加

    将文件或文件夹直接拖入文件列表区域。

文件分组

文件列表通过分组标题（Header）进行组织，用于归类相关样本。用户可通过拖拽方式调整文件所属分组。

文件排序

  • 单击 "Reorder" 按钮以启用排序模式
  • 在列表中拖动文件以调整顺序
  • 关闭 "Reorder" 以锁定当前顺序

3.1.3 参数与执行面板（右侧区域）

该区域用于参数配置与命令执行。

基础参数

  • 输入文件路径
  • 输出文件路径
  • 必要参数设置

进阶参数

  • 各工具的扩展参数设置

命令生成与执行

  • 单击 Generate 生成命令
  • 单击 Run 新建终端并执行命令

3.2 分析前准备

在正式运行分析流程前，需要准备 Kraken2 数据库及 NCBI 分类学信息。

3.2.1 Kraken2 数据库

Kraken2 数据库可通过以下两种方式获取：

1. 自行构建

使用以下命令构建数据库：

  • k2 download-library
  • k2 download-taxonomy
  • k2 build

基本流程包括下载参考基因组、获取 taxonomy 信息并构建索引。

2. 下载预构建数据库

可以从 AWS 索引页面下载预构建数据库：

https://benlangmead.github.io/aws-indexes/k2

适用于快速部署场景。

3.2.2 数据库构建建议

建议采用分库策略：

  • 构建宿主专用数据库，用于宿主去除
  • 构建病原候选数据库，用于物种分类

3.2.3 NCBI 分类学信息（taxdump）

taxonomy 数据可通过以下方式获取：

  • 官方下载：ftp://ftp.ncbi.nih.gov/pub/taxonomy/taxdump.tar.gz
  • k2 download-taxonomy
  • retaxdump（Recentrifuge 工具）

应确保 taxonomy 数据版本与数据库构建版本一致。

3.3 标准分析流程

以下步骤描述一次完整分析过程。

步骤 1：导入数据

在左侧文件管理区域添加 FASTQ 文件以及存放参考数据库的文件夹。

步骤 2：选择分析模式

根据需求选择运行方式：

  • 在 Tools 页面运行单个工具
  • 在 Flow 页面运行预设分析流程

步骤 3：设置参数

在参数面板中：

  • 配置输入与输出路径（通过从左侧文件列表拖拽并释放于目标输入组件）
  • 设置必要参数
  • 根据需要调整进阶参数

步骤 4：生成并执行命令

  1. 单击 Generate 生成命令
  2. 检查命令预览
  3. 单击 Run 启动终端并执行分析

3.4 结果查看与判读

分析完成后，结果文件将输出至指定目录。

3.4.1 可视化结果

Recentrifuge 输出 Krona-like 交互式 HTML 饼图，用于展示分类层级结构与相对丰度信息。该图表支持：

  • 多样本对比
  • 阴性对照比较
  • 衍生样本分析

3.5 病原判读建议

在进行潜在病原判读时，可依托 Recentrifuge 生成的交互式 HTML 饼图，通过以下三类信息进行分析：

  • CTRL：显示病例样本减去阴性对照后的分类结果，可用于识别在阴性样本中不存在的候选病原。
  • EXCLUSIVE：显示每个样本独有的物种，有助于发现特异性候选病原。
  • SHARED_CTRL：显示不同样本之间共享且经过对照处理的物种信息，用于判断可能的共性或污染。

理想情况下，应重点关注病例样本中出现的 CTRL 和 EXCLUSIVE 物种，同时结合 SHARED_CTRL 信息确认物种是否在其他样本中共享，从而提高潜在病原判读的可靠性。

4 错误排查

在使用 Viscan 过程中，可能遇到安装、配置或运行问题。常见问题及排查方法如下：

4.1 工具未找到或不可用

症状：Status 页显示工具状态为 Not Found。

排查方法：

  1. 检查 Config 页中对应工具的路径是否正确。
  2. 确认该工具已安装并且可在 WSL 中运行。
  3. 如有必要，重新运行 Install 页安装流程。

4.2 WSL 无法连接

症状：执行命令时提示无法访问 WSL 或命令失败。

排查方法：

  1. 确认 WSL 已启动，并能在命令行中正常执行 wsl 命令。
  2. 检查 Config 页中 WSL 可执行文件路径及发行版名称是否正确。
  3. 系统 RAM 不足时也可能导致 WSL 无法正常连接，可尝试清理系统内存后重启 WSL。

4.3 数据文件或路径问题

症状：导入文件失败或分析报错。

排查方法：

  1. 确认文件路径正确，避免特殊字符或空格导致路径解析失败。
  2. 使用支持的文件格式（如 FASTQ、FASTA 等）。
  3. 文件路径无法访问时，尤其是 /mnt 下的外接硬盘，可能未被 WSL 识别，重启 WSL 通常可以解决。
  4. 文件导航列表右键菜单检查 Windows 与 WSL 路径转换是否正确（Viscan 会自动转换，但手动路径可能出错）。

4.4 分析命令执行错误

症状：终端执行命令报错。

排查方法：

  1. 查看终端输出的错误信息，确认依赖工具和参数正确。
  2. 检查所选数据库、参考序列和配置参数是否完整。
  3. 尝试在 WSL 中手动运行相同命令，确认工具环境可用。

附录 A：WSL 配置与使用建议

提升 WSL 性能

可以在 Windows 用户目录下创建 .wslconfig 文件，自定义 WSL2 的资源分配：

[wsl2]
memory=16GB            # 分配给 WSL 的最大内存
processors=8           # 分配 CPU 核心数量
swap=8GB               # 交换空间大小
swapFile=D:\\wsl-swap.vhdx  # 交换文件路径

根据实际计算机配置调整内存和核心数，避免影响 Windows 系统性能。

访问 Windows 文件系统

  • Windows 磁盘在 WSL 中挂载路径为 /mnt/

    例如：C:\Users\data → /mnt/c/Users/data

  • 在 Windows 中访问 WSL 文件，可以使用网络路径：

    \\wsl.localhost\\
